# imgdupe（重複画像検索）

ディスクの中から **同じ画像** と **見た目が同じ画像** を探す Windows 用ツールです。
100 万枚規模でも動くよう C++ で作っています。

**ダウンロード:** [最新版のリリース](https://github.com/sarumogu2013-glitch/1MfilesIMGsearch/releases/latest) から `imgdupe_setup.exe` を落として実行します。

## AI で作ったソフトです

このソフト（ソースコード・テスト・文書・タグの日本語の訳）は、**AI（Anthropic の Claude）が書いたもの**です。人は、作りたいものの指示・仕様の判断・動作の確認をしています。
AI が書いたものなので、思わぬ不具合があるかもしれません。大事な画像は、別に控え（バックアップ）を取ってから使ってください。
このソフトは画像のファイルを書き換えません（読むだけで、解析の結果は自分の DB とドライブの `.imgdupe` に置きます）。

## インストール

- `imgdupe_setup.exe` を実行し、「インストール」を押します。**管理者の権限は要りません**（`%LOCALAPPDATA%\Programs\imgdupe` に入れます。場所は変えられます）。
- **AI の部品**（ONNX Runtime、WD14 タガーのモデル（約 1.3 GB）、CLIP のモデル（約 0.5 GB））は、チェックを入れるとインストールの途中でダウンロードします。
  外しておいて、後から「ツール → 設定… → AI 解析」の「最新版を調べる」で入れることもできます。
- 使うモデルが変わった時は、「アップデートを確認」を押すと（本体が最新なら続けて）AI の部品の新しい版を確かめ、
  変わった部品だけをダウンロードして入れ替えます。ダウンロードしたファイルは SHA-256 を確かめてから使います。
- アンインストールは、Windows の「設定 → アプリ → インストールされているアプリ」の imgdupe から。
  設定と画像の情報（DB・サムネイル）を残すかどうかを聞きます。画像そのものは消えません。
- インストーラーを入れ直すと、同じ場所に上書きします（設定と DB はそのまま）。

画像は **読むだけ** で、移動・削除・書き換えはしません（「フォルダを作成」で作るのは、元の画像を指すハードリンクです）。

### 「Windows によって PC が保護されました」と出た時

exe に電子署名（有料の証明書）が無いため、インターネットから落とした直後は Windows（SmartScreen）が実行を止めます。
次のどちらかで起動できます。

- 出た画面の **「詳細情報」** を押し、**「実行」** を押す（1 回やれば、その exe では次から出ません）
- 実行する前に、`imgdupe_setup.exe` を右クリック → **プロパティ** → 下の **「許可する」** にチェック → OK

## 用語

| 用語 | 意味 |
|---|---|
| 重複チェック | 監視フォルダの中の重複・差分をまとめて出すタブ（「チェック開始」で動かす） |
| 同一画像 / 類似画像（AI） | 中身・見た目が同じ画像 / CLIP で写っているものが近い画像 |
| 内容検索（AI） | 言葉で、写っているものを探す |
| まとまり | 同一画像・差分を 1 つに重ねたもの（完全一致・見た目一致・差分） |
| 検索対象 | フリーワードを当てる所（タグ・タイトル・ファイル名など） |
| 埋め込みタグ / 管理タグ | 画像ファイルに書き込まれているタグ（読むだけ） / imgdupe の DB にだけあるタグ（ファイルは書き換えない） |
| 確定 / 否定 | 管理タグを手で決める（「正しい」「違う」から改めた） |
| タグの由来 | タグがどこから来たか（タガー・json・フォルダ名・手動など）。「出典」とは別 |
| タグトレイ | よく使うタグを置いておく帯（ドラッグで付ける・まとめて検索） |
| 監視フォルダ | 常駐解析が中を見張るフォルダの一覧（「監視をやめる」で外す。解析の結果は残る） |
| 解析 / 常駐解析 / 解析の予約 | ハッシュ・サムネイル・タグ・CLIP などを作ること / タスクトレイで動き続ける解析 / 先に解析してほしいフォルダ・画像の順番待ち |
| 休止中（灰色の印） | 解析の結果はあるが、ドライブがつながっていない・監視をやめたので、結果に出さない |
| 退避 / 復元 | 見つからなくなった画像の解析結果を消さずに別の所へ移す / 見つかった時に戻す |
| 移動の追跡 | 動かした・名前を変えた画像を同じ画像と見分けて、解析をやり直さない |
| ドライブ記録 / PC 記録 | ドライブの `.imgdupe` に置く、そのドライブの解析結果 / このソフトが普段使う DB |
| ドライブへ記録 / ドライブから取り込み | PC 記録の変わった分をドライブ記録へ書く（10 分ごと） / ドライブ記録から PC 記録へ読み込む |
| スマートフォルダ | 名前を付けて保存した検索の条件 |
| リンクフォルダ | 検索結果の画像をハードリンクで並べたフォルダ |
| 再読み込み | 画面の控えを捨てて読み直す（「アップデート」はソフトの新しい版） |

## 使い方

### 画面の作り

画面はいつもエクスプローラー（mgview のファイルエクスプローラーモードと同じ形）です。上のリボンで操作します。

- **リボン**: 「ホーム」（開く・場所を表示・パスをコピー・更新・同一画像を探す・統計・設定などと、表示の設定）、「重複チェック」、「検索」、
  「画像から検索」の 4 つ。タブで切り替えます（Ctrl+3 / Ctrl+1 / Ctrl+2 / Ctrl+4。タブの見出しの上でホイールを回しても移れます。
  下のリボンの上で回しても移りません）。
- **再読み込み**（ホームの「再読み込み」、「表示 → 更新」、Ctrl+F5）: 画面の控え（フォルダの中身・サムネイル・画像の情報）を捨てて、今の場所を読み直します。
  ファイルを移動したのに残っている時や、表示がおかしい時に。検索の結果を出している時は、無くなったファイルを一覧から除きます。
  常駐解析（解析すること）はしません。要る時はタスクトレイの解析から「今すぐ調べ直す」などで。
- **よく行く場所の先読み**: よく開くフォルダとそのドライブの直下は、起動した時に中身とサムネイルを少し先に読んでおき、開いた時にすぐ出します
  （フォルダの中身が変わっていれば読み直します）。
- **ホームのリボン**: 左から 開く・場所を表示・パスをコピー・再読み込み ｜ タグの手動編集（入 / 切）・同一画像を探す ｜ 表示の 4 つのボタン ｜ 設定・キー・アップデート・使い方。
  ボタンの幅は 6 文字分にそろえます（名前が長いものはその分広く）。
- **削除**（v3.12.4。右クリック →「削除（ごみ箱へ）」、ファイル → 削除、Delete キー）: 選んでいるファイル・フォルダを、確かめてからごみ箱に移します。
  重複のまとまりはそのままでは消しません（開いて中の画像を選びます）。消した画像の解析の結果は、常駐解析が見つからなくなった画像として退避します。
- **詳細の範囲選択**（v3.12.5）: Windows のエクスプローラーと同じく、名前（アイコンと文字）の上から押すとファイルを掴んでドラッグ、
  それ以外の白い所（空いている列・名前より右など）から押して動かすと、枠で囲んで選びます。白い所をクリックだけした時は、その行を選びます。
- **ホームの表示の設定**（v3.12）: 表示・ペイン・表紙・並び順の四角いボタンが 4 つあります（Windows 10 のエクスプローラーの「表示」のリボンのような形）。
  押すと選ぶメニューが出て、ボタンの上でホイールを回すと値を順に替えられます。
  - **ペイン**: フォルダ一覧・プレビューを出す / 隠す。
  - **表示**: 詳細か、サムネイルの大きさ（小・普通・大・可変）。ホイールで 詳細 ⇔ 小 ⇔ 普通 ⇔ 大 ⇔ 可変。
  - **並び順**: 名前・更新日時・種類・サイズ（検索の結果では「検索結果の順」も）と、昇順 / 降順。ホイールで種類を替えます。
  - **表紙**: フォルダのサムネイルに、中のどの画像を出すか（5 通り）。ホイールで替えます。
  - 同じものは「表示」のメニューにもあり、ショートカットキーも割り当てられます。
  - 下のステータスバーの右端のアイコンでも、フォルダ一覧・プレビューの出す / 隠す、サムネイル / 詳細の切り替えができます。
- **エクスプローラー**: 上に戻る・進む・上へとアドレスバー（フォルダの階層ごとのボタン。クリックでそのフォルダへ、
  掴んでドラッグするとそのフォルダをエクスプローラーなどに落とせます。空いた所のクリック（Ctrl+L）でパスを文字で入力、右クリックでパスのコピー）。左にフォルダ一覧（Shift + ホイールで横にスクロール）、真ん中にサムネイルか詳細（Windows のエクスプローラーの「詳細」と同じ列。どの列も見出しのクリックで並べ替え、見出しの境目のドラッグで幅を変えられます（ダブルクリックで既定の幅。幅は次に起動した時も残ります）。列が一覧より広い時は横にスクロールできます（下のスクロールバー、Shift + ホイール、チルトホイール）。ホイールは 1 目盛りで 1 行）、
  右にプレビュー、下にステータスバー（フォルダの中の数・検索の結果の数など）。表示・並び順・パネルの開け閉めや幅は覚えます（`imgdupe.ini` の `[Explorer]`）。
- **いくつも選ぶ**: Ctrl を押しながらクリックで 1 つずつ足す・外す、Shift を押しながらクリック（Shift + 矢印）で範囲、
  空いている所からドラッグして枠で囲む（Ctrl を押していれば今の選択に足す）、Ctrl+A で全部、Esc でやめる。
  選んだものを右クリックすると、パスをまとめてコピー・**選んだ画像をスマートフォルダに保存**・選んだ画像にタグを付ける・否定する ができます
  （「画像 → 選んだ画像をスマートフォルダに保存」、Ctrl+Shift+M でも）。保存したスマートフォルダは、検索の「スマートフォルダ」から開くと
  その画像を出します（ほかの条件と組み合わせられます。「条件をクリア」で外れます）。解析に無い画像は保存・タグ付けできません。
- **解析の印**（サムネイルの右下。詳細表示では「解析」の列）: 緑のチェック = 解析済み（進み具合 100%。検索などの結果に出る）、橙 = 解析待ち（100% でないもの）、白 = 未解析、半分が緑 = 一部、
  灰色のチェック = 休止中（解析はあるが、監視フォルダの外なので結果に出ない。監視フォルダに足すとすぐ緑に戻る）。
  詳細表示の「解析」の列には、解析の進み具合も出します: 画像は `[85%] 6/7 種類`（済んだ解析の種類 / 解析の種類）、
  フォルダは `[55%] 3,850/7,000（1,000 枚×7 種類）`（下の階層の全部の画像の、済んだ種類の延べ数 / 枚数×種類）。
  % は、解析の種類ごとの 1 枚の処理の時間の目安で重みを付けた値です（タガーが一番重く、名前の解析はほぼ 0。残りの時間の割合の目安）。
  解析の種類は、ハッシュ・サムネイル・メタデータ・json とフォルダ名と、入れてあるタガー・CLIP・品質。裏で数えます（同じフォルダは 15 秒に 1 回）。
  右クリックの「このフォルダを解析する」で、そのフォルダを監視フォルダに足せます。
  フォルダをいくつも選んで右クリックすると「選んだフォルダ（N 個）の解析する」で、まとめて足せます。
- **外へドラッグ**: 選んだファイル（いくつでも）をドラッグして、エクスプローラーやほかのアプリにドロップできます（コピーかショートカット。移動はしません）。
- **プレビューの切り替え**: プレビューの上の「画像だけ」「タグ」「プロパティ」で、出すものを切り替えます（覚えます）。
  「プロパティ」は大きさ・ファイルサイズ・日時・形式・撮影の情報（カメラ・レンズ・ISO など）・品質・同じ画像の数などを表にします。
- **タグ**: 画像を選ぶと、プレビューの名前のすぐ下に「埋め込みタグ」と「管理タグ」を出します（色は種類: 作者 赤、キャラ 緑、作品 紫、一般 青）。
  タグをクリックすると、そのタグで検索します。検索の後も、クリックした時に選んでいた画像（か、それを含むまとまり）を選んだままにします。
- **検索の結果のまとまり**: 検索の結果では、同じ画像（完全一致・見た目一致）と差分（AI）を 1 つのまとまり（重なったカードと枚数の印）にまとめて出します。
  ダブルクリックで中の画像を一覧にし、「戻る」で結果に戻ります。まとまりを選んでドラッグ・保存・タグ付けすると、中の画像全部が対象です。
- **タグの日本語表示**: タグ（WD14 タガーの英語のタグ）は日本語の表示名で出します（`long_hair` → ロングヘア、`hatsune_miku` → 初音ミク など。
  一般のタグは全部、キャラは分かるものを同梱。タグそのものは英語のまま DB に持ち、ファイルにも書き込みません）。
  設定の画面の「全般」（Ctrl+J でも）で、英語の表示に切り替えられます。
  タグを右クリックして「表示名を変える…」で、自分で付けた名前にできます（空にすると同梱の訳に戻ります）。
- **タグトレイ**: プレビューのタグをドラッグして、上の「タグトレイ」の帯に置けます（右クリックの「タグトレイに置く」でも）。
  タグトレイのタグを掴んで画像に落とすと、その画像に管理タグとして付けます（手動で「確定」と確定。確度 1.0。選んでいる画像の上なら選んでいる画像全部、
  プレビューの上ならプレビューの画像に。Ctrl+Z で戻せます）。検索のフリーワードの欄に落とすと、語として足します（探すのは Enter か「検索」で）。
  タグトレイのタグはクリックで使う・使わないを切り替え、「タグをまとめて検索」で、使うタグを全部持つ画像を探します（× で外す、「クリア」で全部外す）。
- **タグの手動編集**（v3.11。「ツール → タグの手動編集」、画像の右クリック →「タグの手動編集」）: 入れている間、プレビューのタグで手でタグを直せます。
  - タグをクリックすると **確定 → 否定 → そのまま** の順に切り替わります（確定 = 緑と ✓、否定 = 赤と ×・取り消し線、そのまま = いつもの見た目）。
    確定・否定はタグの由来「手動で確認」になり、ほかの由来より優先されます。そのままにすると、手の決定を外して AI の判断に戻します。
  - さわれるのは AI が付けたタグ（WD14 タガー・辞書・CLIP・見本画像との類似）と、手で決めた・足したタグだけです。
    フォルダ名・ファイル名・出典・親子関係・埋め込みタグなどは**灰色**で、変わりません（直す時は元の決まりを直します）。
  - 管理タグの最後の「＋」で、タグを打って足せます（表示名でも）。タグトレイのタグをプレビューか選んでいる画像に落としても、確定として足せます。
  - まだ保存していない変更は点線の枠で出し、上に「タグの手動編集中（変更 N 件）」と「保存」「取り消す」を出します。
    保存しないまま、別の画像を選ぶ・フォルダを移る・タブを替える・編集を切る・閉じる時は「編集したタグを保存しますか？」（はい / いいえ / キャンセル）と聞きます。
    キャンセルなら、何もせずに編集に戻ります。保存した分は Ctrl+Z でまとめて元に戻せます。
  - 画像をいくつも選んでいる時は、選んだ全部の画像に当てます。同じタグの確度・状態が画像ごとに違えば、低いほうを出します。
    全部に付いていないタグは「3/5」と出し、確定にすると付いていない画像にも付けます（灰色の由来だけで付いている画像は変えません）。
  - ファイルに書き込まれているタグは書き換えません（imgdupe の中だけ）。
- **いくつも選んでいる時のプレビュー**: 一覧で一番前の画像を重ねた絵にして「N 枚」と出します。タグは選んだ画像の分をまとめ（全部に無いものは「3/5」）、
  プロパティは全部にある項目だけを出します（値が違えば「複数のプロパティ」）。「画像だけ」では、名前・情報・解析の印を出しません。
- **同一画像を探す**: 次の時だけ、その画像と同じ画像（完全一致・見た目一致）を、今いるフォルダに関係なく、解析した全部のフォルダから探して、
  エクスプローラーの真ん中に一覧で出します（元の画像を先頭にして選びます。「戻る」で元のフォルダへ）。
  - 画像を右クリックして「同一画像を探す」（リボンの「同一画像を探す」、Ctrl+M でも）
  - 画像のファイルをドラッグ＆ドロップする（Ctrl+V で貼り付けても）
  - 画像の URL を入れる（アドレスバーに打つ、ブラウザーから画像をドロップする、URL を Ctrl+V で貼り付ける）

### 検索

「検索」のリボンで探します。結果はエクスプローラーの真ん中に出ます（「戻る」で元のフォルダへ。多い時は先頭の 2 万件）。

- **フリーワード**: 空白で区切った語の全部に合う画像を、関連度の順に出します（タグ・タイトル・本文・ファイル名から探します。
  `hatsune` で `hatsune_miku` のように、語を含むタグにも合います。日本語の表示名でも探せます（`ロングヘア` で `long_hair`、`髪` で表示名に「髪」を含むタグ）。
  `-語` と、横の **除く語** の欄の語は、合う画像を除きます）。Enter か「検索」で探します。
  - `"long_hair"` のように **" で囲んだ語** は、そのタグの名前どおり（別名・日本語の表示名を含む）にだけ合います。
    プレビューのタグをクリックした時や、タグトレイの「タグをまとめて検索」では、この形でフリーワードの欄に入れて探します。
  - プレビューのタグ・タグトレイのタグを、フリーワードの欄にドラッグすると語として足します（探すのは Enter か「検索」で）。
- **検索対象**: フリーワードの右の選択（すべて / タグだけ / タグだけ（名前どおり） / 埋め込みタグだけ / タイトルだけ / ファイル名・フォルダ名だけ）で、
  詳細検索の「検索対象」のチェックをまとめて変えます。チェックは、タグのタグの由来（タガー・json とメタデータ・フォルダ名・フォルダ名からの推定・ID 照会と逆画像検索・
  辞書など・ファイル埋め込み。手動で確定したタグはいつも使う）、タグの部分一致、タイトル、本文、ファイル名、フォルダ名（名前が合うフォルダを結果の先頭に出す）。
  チェックを自分で変えると「カスタム」になります。
- **点数**: タグにそのまま合うと確度、語を含むタグは語の確からしさ（短い語・よく使う文字は低く、長い語・珍しい漢字は高く。1〜2 文字の英数字では部分一致しない）、
  タイトル・本文・ファイル名は 1.0。語ごとに一番高い点数を足したものが関連度です。
- **このフォルダ内に限る**: 3 段目のチェックを入れると、右の欄のフォルダとその下の階層の画像だけから探します。欄にはエクスプローラーで今いるフォルダが入ります
  （検索の結果を出している間は、探す前のフォルダのまま。打って変えることもできます）。
- 条件を全部空にして探すか「**検索を終了**」を押すと、検索の結果を出す前に見ていたフォルダに戻ります。「条件をクリア」は入力欄を初めの状態に戻すだけで、探しません（並び順と確度はそのまま）。
- 詳細検索の「検索対象」の一覧は、ホイールでゆっくり（普段の 1/2）動きます。
- **いつ探すか**: 並び順・降順を変えると、すぐ探し直します（条件が空なら何もしません）。確度スライダーは、止めてから 0.3 秒で探します（横の「既定」で 0.50 に戻します）。
  検索対象の選択とチェック・詳細検索の欄・内容検索・このフォルダ内は、「検索」か Enter（検索のリボンのどこにフォーカスがあっても）で探します。スマートフォルダは、選ぶとリボンに戻すだけです。
- **漫画本文を除く**（3 段目のチェック。v3.6）: 漫画（本のフォルダ）の本文のページを、検索の結果から除きます（表紙・背表紙は残します）。
  フォルダ名が `[サークル名] 本の名前` などの形のフォルダの画像に、解析が表紙・本文・背表紙の印（種類 page のタグ）を付けているものを使います。
  変えると少し待って探し直します。次に起動した時も残り、スマートフォルダにも保存されます。
- 検索の様子（検索中・件数など）は、下のステータスバーに出します。
- **並べ替え**: 関連度（既定）・ファイル名・パス・更新日時・作成日時・撮影日時・解像度・ファイルサイズ・星・タイトル・確度・見栄え・実質の解像度。
- **詳細検索**（「詳細検索 ▼」で開く。普段は隠す）: 星・形式・品質・幅・ファイルサイズ・ダウンロード元・日付（撮影日 / 更新日時 / 作成日時を選んで範囲）・
  未分類・出典切れ・確度・検索対象。「パス（一部）」の欄は v2.22 でなくしました（フリーワードと「このフォルダ内に限る」で代わりに）。詳細検索の条件は、変えてもすぐには探しません（「検索」か Enter で探します）。
  - 日付は、左のチェックを入れると使います（最初は 1 年前〜今日）。年・月・日それぞれの上でマウスのホイールを回すと、その欄が 1 ずつ変わり、
    チェックも入ります（クリックして ↑↓ キーでも。←→ で欄を移り、PageUp / PageDown で 10 ずつ、Space でチェック）。
- そのほか、内容検索（AI）、スマートフォルダ、フォルダを作成は、検索のリボンの 2 段目にあります。
  ボタンや入力欄にマウスを乗せると、簡単な説明が出ます。
- **スマートフォルダの管理**: 「スマートフォルダ」の横の「管理…」（「ツール → 検索 → スマートフォルダの管理」でも）で、削除・並べ替え（上へ / 下へ）・名前の変更・
  書き出し（JSON のファイル）・読み込みができます。並べた順が「スマートフォルダ」の一覧の順になります。読み込みで同じ名前があれば上書きします。
- タグを手で直すのは「タグの手動編集」です（v3.11 で確認キュー・確定 / 否定・タグ… をやめて、これにまとめました）。

### 画像から検索

「画像から検索」のリボンで、手元の画像（解析に無い画像でも）から探します。

- **画像を足す**: 「貼り付け」（Ctrl+Shift+V。スクリーンショットやブラウザーでコピーした画像、コピーした画像のファイル、画像の URL）、
  「ファイル」、「URL」、またはリボンの真ん中に画像をドロップ（エクスプローラー・ブラウザーから。ブラウザーの画像は URL からダウンロード）。
- 足した画像は `imgdupe.ini` と同じ場所の `query` フォルダに置き、**10 枚まで、か 1 日分の少ない方**だけ残します（古いものから消えます）。
  クリックで選ぶと右のプレビューに出します（タグ・プロパティも）。右クリックで消す・開く、ダブルクリックで開きます。
- **同じ画像**: 選んだ画像と同じ画像（完全一致・見た目一致）を、調べた全部のフォルダから探してエクスプローラーの一覧に出します。
- **類似画像（AI）**: 選んだ画像に類似画像を CLIP で探して、エクスプローラーに似ている順に出します（検索のリボンの条件も使います）。
- **タグを生成（AI）**: 選んだ画像に WD14 タガーでタグを付けて、右に出します（キャラ・作品・作者・一般。日本語の表示名で。ファイルにも DB にも書きません）。
- 最初の 1 回は、AI のモデルを読むので数秒かかります。

### 重複チェック

「重複チェック」のリボンで使います。結果は、エクスプローラーの真ん中に、まとまり（重なったカード。ダブルクリックで中の画像）で出します。

1. 監視フォルダは、ホームでフォルダを右クリックして「解析の予約に追加」で足します（「ファイル → フォルダを解析の予約に追加」、
   ウィンドウへのドラッグ＆ドロップでも）。外す時は、監視フォルダを右クリックして「監視をやめる」（ファイル → 監視フォルダの管理 でも）。
   exe のアイコンにフォルダをドロップした時は、そのフォルダを足してすぐに検索を始めます。
2. 「チェック開始」を押すと、同じ画像のまとまり（グループ）を左に出します。
   - **完全一致**: 中身がまったく同じファイル
   - **見た目一致**: 縮小・再圧縮・形式の違い（JPEG と PNG など）・EXIF の回転があっても見た目が同じ画像
   - グループは「消せば空く容量」（一番大きいファイル以外の合計）の大きい順に並びます
3. グループを選ぶと、右にサムネイルを出します。ダブルクリック（または Enter）で開き、右クリックで「エクスプローラーで表示」「パスをコピー」ができます。
4. 「結果を書き出す」で CSV と、サムネイル付きの HTML を書き出します。

- **差分（AI）も出す**: CLIP を入れてあれば、表情違い・服違い・少し描き直したものなど「同じではないがとても似ている」画像のまとまり
  （差分）も、重複の後ろに出します。常駐解析が作っておくものです。同じ重複のまとまりの中だけで閉じているものは出しません。
  どれくらい似ていれば差分とみなすかは「ツール → 設定… → AI 解析」で変えられます（既定 0.92。大きいほど厳しい）。

よく使う操作はリボンにあります（「重複チェック」: チェック開始／中止・1 枚の重複チェック・結果を書き出す、「ホーム」: 開く・場所を表示・パスをコピー・
更新・同一画像を探す・統計・設定・キー・アップデート・使い方）。ボタンにマウスを乗せると簡単な説明が出ます。

## 検索

「検索」のタブ（Ctrl+2。「重複チェック」は Ctrl+1）で、常駐解析が読み取った情報から画像を探せます。
条件を変えると、少し待ってからすぐに結果のサムネイルが出ます（多い時は先頭から出し、残りは裏で読み込みます）。

- **タグ**: 空白で区切って並べると、すべてのタグを持つ画像。`-タグ` はそのタグを持たない画像。別名（`初音ミク` と `hatsune_miku` など）はまとめて扱います。
- **確度**: スライダーを右へ動かすほど、確実なタグだけで探します。同じタグが複数のタグの由来から付いていれば、
  `1 - (1 - p1)(1 - p2)…` で確度を合成します。手動で確定したタグは、その値（1.0 / 0）をそのまま使います。
- **タグの由来**: チェックを外したタグの由来は、確度の計算に入れません（「タガーの推測は除外」など）。
- **文字**: タイトル・件名・コメント・キーワード・PNG に埋め込まれた文字（プロンプトなど）の部分一致。
- **星・形式・撮影日・幅・ファイルサイズ・パス・ダウンロード元** で絞り込み、パス・更新日時・作成日時・撮影日時・解像度・
  ファイルサイズ・星・タイトル・確度で並べ替えられます（並べ替えは DB の中で行うので、100 万枚でもすぐ返ります）。
- 画像を選ぶと、下にパス・解像度・撮影日時と、タグを 2 行に分けて出します。
  - **埋め込みタグ**: 画像ファイルに書き込まれているタグ（XMP / IPTC / EXIF のキーワード。エクスプローラーの「タグ」と同じもの）。読むだけで、変えません。
  - **管理タグ**: タガー・フォルダ名・json・手動の確定など、imgdupe の DB にだけあるタグ（合成した確度と、タグの由来ごとの確度）。
    ファイルには書き込みません（タグの手動編集で変わるのもこちらだけです）。
  - どちらのタグも検索に使えます（埋め込みタグはタグの由来「ファイル埋め込み」、確度 0.90）。タグの由来のチェックで、片方だけにもできます。
  ダブルクリックで開き、右クリックで「エクスプローラーで表示」「パスをコピー」ができます。
- 条件は次に起動した時も残ります。
- **内容検索（AI）**: 「夕焼けの海」「犬と猫」などの言葉で、画像の内容が近い順に探します（CLIP。日本語・英語など 50 以上の言語）。
  タグが付いていない画像でも、写っているものが近ければ見つかります。
  ほかの条件（タグ・星・パスなど）と組み合わせると、その条件に合う画像の中から近い順に、上位 2,000 件を出します。
  最初の 1 回は言葉側のモデルを読むので数秒かかります。
- **類似画像を探す**: 結果の画像を右クリック →「類似画像を探す」で、その画像に見た目・内容が近い順に並べます（元の画像を先頭にして選びます）
  （切り抜き・色調補正・構図違いなど、重複の検索では見つからないものも出ます）。画像の下に「似ている度合い」を出します。
  今いるフォルダに関係なく、CLIP のベクトルのある全部の画像から探します（検索のリボンの条件はクリアしてから探します）。
  探す画像のベクトルを常駐解析がまだ作っていない時は、その 1 枚だけその場で作ってから探します。
- **未分類（タグなし）**: 確度スライダーの値以上のタグが 1 つも無い画像だけを出します（どの判定にも自信が無い画像。タグの由来の絞り込みも効きます）。
- **元に戻す**（Ctrl+Z、「ツール → タグの操作を元に戻す」）: タグの手動編集・タグトレイから付けた操作を、新しいものから 1 つずつ取り消します（`imgdupe.db` の history に残します）。
- **スマートフォルダ**: 「保存…」（Ctrl+Shift+S）で今の条件に名前を付けて保存し、左上の一覧から選ぶといつでもその条件で探せます。
  保存するのは条件だけなので、画像が増えたりタグが付いたりすると、中身も自動で最新になります。「削除」で消しても画像は消えません。

## AI タグ辞書（行動・アイテム）

「ツール → AI タグ辞書（行動・アイテム）…」で、WD14 のタグと CLIP の文章を自分の分類にまとめられます（`dictionary.txt` に保存）。

```
[テニスをしている]
種類: action
wd14: tennis_racket, tennis_ball, tennis_uniform
clip: "a person playing tennis", "テニスをする人"
```

- `wd14:` のタグのどれかが付いている画像に、`[ ]` の名前のタグを付けます（タグの由来「辞書」、確度はその中で一番高いもの）。
- `clip:` の文章と画像の内容が近い画像にも付けます（タグの由来「CLIP」。近さを確度にします。日本語でも英語でも）。
- 「保存して当てる」で、すべての画像に当て直します（画像は読み直さないので、数秒〜数十秒）。新しい画像には、常駐解析が当てます。
- 付けたタグは検索用のタグで、ファイルには書き込みません。検索の「タグ」に `テニスをしている` と入れると探せます。

## タグの別名・親子

「ツール → タグの別名・親子…」で、タグどうしの関係を書けます。

```
初音ミク = hatsune_miku      （別名: 検索ではどちらでも同じタグとして探します）
hatsune_miku > vocaloid      （親子: 左が付いた画像には右も付けます。確度は左と同じ）
```

- 親子関係で付けたタグはタグの由来「親子関係」です（親の親までたどります）。検索用のタグで、ファイルには書き込みません。
- 「Danbooru から取り込む」で、Danbooru で使われている別名と親子関係の一覧（数万件）を取り込めます。
  相手の負担にならないよう 1 秒に 1 回ずつ取るので数分かかります。もう一度押すと、新しい一覧に入れ替えます。

## 見本画像

CLIP を入れてあれば、見本の画像に近い画像に、そのタグを付けます（タグの由来「見本画像との類似」）。タガーが知らない新しいキャラや、
作者（画風）も、見本を足すだけで探せるようになります。

- 「ツール → 見本画像のフォルダを開く」で開くフォルダに、`キャラ名` や `作者名` のフォルダを作り、その人の画像を 10〜30 枚入れます。
- タグの手動編集で「確定」にした画像（同じタグに 3 枚以上）も、自動でそのタグの見本になります（「否定」と確定した画像は見本にしません）。
- 名前ごとに見本の CLIP のベクトルを平均し、それに近いほど高い確度にします。常駐解析が、見本が変わった時に当て直します。

## 本のフォルダの名前（漫画・同人誌）

フォルダ名が次の形なら、本のフォルダと見なして、サークル・作者・タイトル・イベント・原作のタグと、ページの役目（表紙・本文・背表紙）を付けます。

```
(イベント)(原作) [サークル名(作者名)] 本のタイトル (原作)(イベント) [DL版]
```

- `[ ]` の部分が要ります（無いと本と見なしません）。`[サークル名(作者名)]` か `[作者名]`。作者は「,」で区切れば何人でも。
- 前後の `( )` は何個でも。`C102`・`c97`、コミケ・例大祭・コミティア・COMIC1・サンクリ・紅楼夢・こみトレ・スパコミ・ボーマス・M3 など約 50 の即売会の名前と
  `2023` のような 4 桁の年はイベント、ほかは原作（パロディ）と見なします。後ろの `[DL版]` などは読み飛ばします。残りがタイトルです。
- 全角のかっこ（`【】`・`［］`・`（）`）も半角と同じに扱います。
- 例: `[ABCサークル(山田太郎)]夏の本(C102)`、`(C97) [サークル (作者)] タイトル (東方Project) [DL版]`、`【作者名】タイトル`
- 本と見なさない例: `山田太郎 - 夏の本`（`[ ]` が無い）、`夏の本 [山田太郎]`（`[ ]` が先頭に無い）
- ページの役目: そのフォルダの直下の画像を名前の順（数字は数として比べる）に並べ、1 枚目が表紙、最後が背表紙、ほかが本文（1 枚だけなら表紙）。
  検索の「漫画本文を除く」はこの本文を除きます。

## フォルダ名から作者・アカウントを読み取る

フォルダの名前から、作者名・サークル名と、作者のアカウント（pixiv のユーザー ID、X のアカウント、FANBOX・Fantia・Skeb など）を読み取って、
中の画像（中のフォルダの画像も）に検索用のタグとして付けます（タグの由来「フォルダ名からの推定」。ファイルには書きません）。
AI（Claude など）も通信も使わず、PC の中で決まった形を読むのと、ライブラリの中の数を数えて照らし合わせるだけです。

- 名札つきの ID: `山田 (pixiv 12345)`、`pixiv_12345`、`鈴木【@suzuki_x】` など
- サイト名のフォルダの下（gallery-dl の既定の形）: `pixiv\12345 account\`、`twitter\account\`、`fanbox\creator\` など
- 同じ形の名前が並んだフォルダ: 同じ場所に「数字 名前」のような同じ形のフォルダが 3 つ以上あれば、中の画像から分かっていること
  （gallery-dl の json・出典の照会で分かった作者と作者の ID、pixiv の画像が多いか）と照らして、数字が pixiv の ID か、文字が作者名かなどを決めます
- 作者名とアカウントの対応（同じフォルダ名・json・照会から）で、片方しか分からないフォルダにもう片方を足します
- 教えた形: フォルダを右クリック →「このフォルダ名から作者などを読み取る形を教える」で、名前の部分ごとに役目（作者名・pixiv のユーザー ID など）を選ぶと、
  同じ場所（または、どこでも）の同じ形のフォルダ全部に当てはめます。どう付くかはその場で一覧に出ます。
  教えた形の一覧と削除は「ツール → フォルダ名のルール」から

アカウントのタグは `pixiv:12345`・`x:@name` の形です。タグを右クリック →「アカウントのページを開く」でそのページを開けます。
統計の「アカウント別」でも見られます。違うタグは、フォルダ名のルールで直します（タグの手動編集では、フォルダ名から付いたタグは灰色で、さわれません）。

## 出典の照会（出典を調べる）

「ツール → 設定…」の「出典の照会」のページで有効にすると、常駐解析が投稿サイトに問い合わせて、タグと作者を足します（既定はどちらもオフ）。
タグは DB にだけ保存し、ファイルには書き込みません。

- **ID 照会**: ファイル名の pixiv の ID（`12345678_p0.png`）と Danbooru の MD5（`0123…cdef.jpg`）で、投稿のタグ・作者を調べます（タグの由来「ID 照会」）。
  gallery-dl などの json でタグが分かっている画像は調べません。1 秒に 1 件ずつ、1 回の解析で 300 件までです。
  pixiv はログインしないので、R-18 などログインが要る投稿は調べられません。
- **逆画像検索（SauceNAO）**: 出典の何も分からない画像（カメラで撮った写真は除く）の、縮小したサムネイルを SauceNAO に送ります（タグの由来「逆画像検索」）。
  似ている度合いが 80 以上なら、見つかった pixiv・Danbooru の投稿を照会してタグを付けます。
  API キー（saucenao.com で無料で登録するともらえます）が要ります。無料のキーは 1 日 100 回までなので、設定の「1 日に」の回数を超えては送りません。
- **出典切れの確認**: 出典の pixiv・Danbooru・X の投稿が消えていないかを、30 日ごとに確かめます（同じ投稿は 1 回。1 秒に 1 件ずつ）。
  消えていた画像は、検索の画面の「出典切れ」で探せます（統計の画面にも数を出します）。X は見るのにログインが要る投稿だと分かりません。
- 検索の画面の情報欄に出典のページの URL を出し、画像の右クリックの「出典のページを開く」でブラウザで開けます。
- 一度調べた画像は二度と調べません。検索の画面で画像を右クリックして「出典を調べ直す」を選ぶと、選んだ画像をもう一度調べます。
- 通信できない・回数の上限に達した時は、その回はそこでやめ、次の解析で続きを調べます。

## 品質

常駐解析が、画像の品質を調べます（「設定」の「画像の品質を調べる」。既定はオン。1 枚 0.1 秒ほどかかります）。

- **細かさ**（0〜1）: 画素の細かさまで中身があるか。小さな画像を引き伸ばした（アップスケールした）画像やピンぼけの画像は 0.5 前後になります。
  **実質の解像度** = 長い辺 × 細かさ（2000px でも、1000px を 2 倍にしたものなら 1000px くらい）。
  最近傍法（ギザギザのまま）で拡大した画像は見分けられません。
- **くっきり度**（0〜1）: 長い辺 1024px 以下に縮めて見た時の細かさ。ピンぼけ・手ぶれの画像は低くなります（大きな画像を引き伸ばしただけなら高いまま）。
- **見栄え**（1〜10 くらい）: CLIP のベクトルに [LAION の aesthetic predictor](https://github.com/LAION-AI/aesthetic-predictor)（MIT ライセンス）を掛けた点数。
- 検索の画面の「品質」で、くっきり・ぼやけている（くっきり度 0.5 未満）・拡大・細かさ不足（細かさ 0.75 未満）・低解像度（実質 800px 未満）を選べ、
  並べ替えに「見栄え（AI）」「実質の解像度」があります。情報欄にも値を出します。

## 統計

「ツール → 統計…」で、集めた画像の様子を見られます。常駐解析が 6 時間ごとに集計して残すので、開くとすぐ出ます
（下に「何時の集計か」を出します）。「集計し直す」で今の様子を数え直します（数えている間は % と今数えているものを出します）。

- 上に、画像の数と大きさ、検索用のタグ・出典の分かっている数、重複（完全一致・見た目一致）で重なっている分、解析の進み具合を出します。
- 「表示」で、作者別・キャラ別・作品別・行動・アイテム別の枚数（確度 0.5 以上。手動で「否定」と確定したものは除き、別名は元の名前にまとめる）、
  月ごとの増え方（ファイルの作成日時と更新日時の古い方の月）、形式別を選べます。
- タグの行をダブルクリックすると、そのタグで検索します。

## リンクフォルダ（ハードリンク）

検索の画面の「フォルダを作成」（Ctrl+Shift+E）で、今の検索結果を 1 つのフォルダに並べます。
中身はハードリンク（同じファイルに別の名前を付けたもの）なので、**容量は増えず**、エクスプローラーや他のソフトからは普通のフォルダに見えます。

- フォルダは、画像のあるドライブごとに `ドライブ:\_vfolders\<名前>` に作ります（ハードリンクは同じドライブにしか作れないため）。
  場所は「ツール → 検索 → リンクフォルダ」の「生成先…」でドライブごとに変えられます（選んだフォルダの下に `_vfolders` を作ります）。
- 同じ名前のファイルがぶつかった時は、画像の ID を頭に付けます。同じ名前でもう一度展開すると、今の結果で作り直します。
- **リンク側の画像を編集すると、元の画像も変わります**（同じファイルなので）。
- リンクフォルダは、このソフトを終了すると消えます（一時リンク）。残したい時は「ツール → 検索 → リンクフォルダ」で選んで「固定にする」を押します。
  固定にしたフォルダは、同じ画面の「削除」で消すまで残ります。異常終了で残った一時リンクは、次に起動した時に消します。
- 消すのは、このソフトが作ったリンクで、今も元の画像と同じ中身のものだけです（別のファイルに置き換わっていたら触りません）。
  元の画像が消えて、データがリンクにしか無いものは消さずに残し、「リンクフォルダ」に数を出します（元の画像を消しても容量が空かない状態）。
- `_vfolders` という名前のフォルダは、重複の検索と常駐解析では読みません（同じファイルが重複として出ないように）。
- NTFS のドライブで使えます（FAT32・exFAT・ネットワークのドライブには作れないことがあります）。

## 常駐解析

「ファイル → 常駐解析を始める」で、画像の読み込み（ハッシュとサムネイル作り）を裏で進める常駐処理（indexer）を起動します。
タスクトレイにアイコンが出て、カーソルを合わせると進み具合、右クリックで一時停止・今すぐ調べ直す・終了ができます。

- ハッシュ・サムネイルのほか、撮影日時・カメラ・キーワード（タグ）・星・タイトル・PNG に埋め込まれた文字（画像生成 AI のプロンプトなど）・
  ダウンロード元・ファイル名の投稿 ID（pixiv・X）も読み取って DB に残します（元のファイルは変えません。「検索」のタブで使えます）。
- **AI の部品**を入れてあれば、WD14 タガー（wd-eva02-large-tagger-v3）で画像にキャラ・作品・一般のタグを付けます
  （タグの由来「タガー（WD14）」、確度はモデルの確率。0.2 未満のタグは残しません。レーティングは一番高いもの 1 つ）。
  GPU があれば DirectML で、無ければ CPU で動きます（CPU では 1 枚 1 秒ほどかかるので、100 万枚なら数日かけて裏で進めます）。
  モデルは、まだタグを付けていない画像がある時だけ読み込みます。使うモデルが変わると、全部の画像を新しいモデルで付け直します。
  GPU で調子が悪い時は、「ツール → 設定… → AI 解析」で「GPU（DirectML）を使う」を外すと CPU だけを使います。タグ付けそのものを止めることもできます。
- **CLIP** を入れてあれば、画像の内容をベクトル（512 個の数）にして `vectors_clip.bin` に保存します（100 万枚で約 1 GB）。
  「内容（AI）」と「類似画像を探す」に使います。CPU では 1 枚 0.1〜0.2 秒ほどです。
  タグ付け（WD14）と CLIP は、残りが多い時は交互に、それぞれ約 10 分ずつ進めます（片方が全部済むまで、もう片方が何日も始まらないことの無いように。
  タガーは重く CLIP は軽いので、枚数は測った速さで決めます）。
- **AI の部品の更新**: 部品の版が変わっても、ファイルの中身が前と同じなら入れ直さず、タグ・CLIP のベクトルも作り直しません
  （中身を `models\installed.json` の sha256 で比べます）。中身が本当に変わった時だけ、新しいモデルで付け直します。
- CLIP のベクトルから近似最近傍の索引（`ann_clip.hnsw`。hnswlib）を作り、差分のまとまりを探します。新しい画像だけを足していきます。
- 画像の横に gallery-dl などが書いた json（`画像.jpg.json` か `画像.json`）があれば、作者・タグ・タイトル・投稿 ID を読みます
  （タグの由来「メタデータ」、確度 0.95。pixiv・X（Twitter）・Danbooru 系の形に対応）。
- 画像のあるフォルダの名前もタグにします（タグの由来「フォルダ名」、確度 0.70）。
  `Downloads`・`画像`・日付や数字だけの名前などは使いません。
- **同人誌などの形のフォルダ名**: `[サークル名(作者名)]タイトル(イベント名等)` の形なら、サークル・作者・タイトル・イベント・原作を
  それぞれのタグにします（確度 0.95）。
  - 例: `[ABCサークル(山田太郎)]夏の本(C102)` → サークル「ABCサークル」・作者「山田太郎」・タイトル「夏の本」・イベント「C102」
  - 先頭の `(C99)` のようなイベント、後ろに続く `( )` もいくつでも読みます。`( )` の中が C＋数字・コミケ・例大祭・COMIC1・コミティア・
    年の数字などイベントらしいものはイベント、ほか（`東方Project` など）は原作（作品のタグ）にします。`[DL版]` などの後ろの `[ ]` は読み飛ばします。
  - `[作者名]タイトル` のように `( )` の無いものは作者だけ、作者が `山田、佐藤` のように並んでいればそれぞれ。全角の 【】（）も同じです。
  - 中のフォルダ（`…夏の本(C102)\01\001.jpg` など）の画像には、上へたどって最初に見つかったこの形のフォルダのタグを付けます。
  - **本のページ**: この形のフォルダの直下の画像は、名前順（数字は数として。2 は 10 より前）で 1 枚目に「表紙」、最後に「背表紙」、
    ほかに「本文」のタグを付けます（1 枚だけなら表紙）。後から画像を足した時は、足した画像だけがその時の並びで付きます。
  - タグの色: サークル 暗い赤、タイトル 青緑、イベント 茶、ページ 紺。「統計」にサークル別・イベント別・タイトル別もあります。
- 画面で追加したフォルダを見張り、画像が増えたり変わったりすると、少し静かになってから読み込みます（変化が無くても 30 分ごとに確かめます）。
  先に済ませておくので、「チェック開始」がすぐ終わります。
- **処理の負荷**は 3 段階から選べます（「ツール → 設定… → 常駐解析」の「処理の負荷」、タスクトレイの右クリックの「処理の負荷」）。

  | 負荷 | 操作している間 | 操作していない時 | 優先度 | 全画面のアプリ中・バッテリー |
  | --- | --- | --- | --- | --- |
  | 控えめ（既定） | 1 スレッド | 全部のコア | 最低（CPU・ディスクとも下げる） | 休む |
  | そこそこ | コアの半分 | 全部のコア | 通常以下 | 休む |
  | しっかり（ゲーム並み） | 全部のコア | 全部のコア | 通常（ゲームなどと同じ） | 休まない |

  上げるほど早く終わりますが、そのぶんほかのアプリが重くなります。GPU（DirectML）はどの段階でも使います。いつ止めても続きから再開します。
- **CPU と GPU を同時に使います**: ハッシュ・サムネイル・メタデータ・品質（CPU）と、タグ付け・CLIP（GPU）を別々に同時に進めます
  （「控えめ」で操作している間だけは、1 スレッドで順に進めます）。タスクトレイの窓の「新規作成中」に、両方の段階と進み具合を出します。
- タグ付け・CLIP は、画像を読んで縮める所（CPU。いくつものスレッド）と推論（GPU）を分け、GPU には 8 枚（CLIP は 16 枚）ずつ
  途切れないように続けて流します。1 枚ずつ流して GPU が動いたり止まったりを細かく繰り返すと負荷が波打ち、グラフィックカードから
  音（コイル鳴き）が出ることがあるためです。まとめて流せないモデルや、GPU のメモリが足りない時は、自動で 1 枚ずつに戻します。
  「控えめ」で操作している間（画像を読むのが 1 スレッドで遅い時）は、32 枚（CLIP は 64 枚）たまってから続けて流し、その間は GPU を休ませます
  （数枚ごとに動いたり止まったりを繰り返さないように）。
- 「Windows と一緒に常駐解析を始める」にチェックを入れると、ログオンの時に起動します（管理者権限は要りません）。
- 画面を閉じても、解析が終わっても動き続けます（新しい画像を見張ります）。止める時はメニューかタスクトレイから止めます。
- **タスクトレイのアイコンをクリック**すると、小さな窓で解析作成の状況が分かります（ダブルクリックで画面を開く）。
  「新規作成中」は今の処理（段階・進み具合・速さ（枚/秒）と残りの時間の目安・負荷）、「総合」は全部の画像について段階ごとに済んだ割合を出します。ほかの所をクリックすると閉じます。
- 中身は同じ `imgdupe.exe` を `--indexer` を付けて起動したものです（アップデートも一緒に済みます）。

### 解析の予約（解析する順番）

フォルダや画像を「解析の予約」として足すと、常駐解析は**上のタスクから 1 つずつ**、その中の画像だけを全部の段階
（ハッシュ〜タグ付け・CLIP・品質）まで済ませます。タスクが無くなってから、いつもどおり監視フォルダ全体の変化を見ます。

- 足し方（1 回の操作で 1 つのタスクになります）
  - ホームでフォルダを右クリック →「解析の予約に追加」/「解析の予約の一番上に追加（最優先）」
    （監視フォルダの外のフォルダは、監視フォルダにも足します。中のフォルダなら、そこを先に済ませるだけです）
  - 画像を 1 つ右クリック →「この画像を解析する（最優先）」
  - いくつも選んで右クリック →「選んだもの（フォルダ N 個・画像 N 枚）を解析の予約に追加」/「…一番上に追加」
  - 「ファイル → フォルダを解析の予約に追加…」（Ctrl+O）/「フォルダを最優先で解析…」（Ctrl+Shift+O）、ウィンドウへのドラッグ＆ドロップ
- 一番上に足すと、今のタスクを切りのよい所（256 枚ごと）で止めて先に済ませます（止めたタスクは後で続きから）。
- **一覧と並べ替え**: タスクトレイの窓の「タスク」（「ファイル → 解析の予約の一覧」、トレイの右クリックの「解析の予約の一覧」でも）。
  行をドラッグして並べ替え、右クリックで「一番上へ（最優先）」「1 つ上へ」「1 つ下へ」「一番下へ」「タスクから外す」。処理中の行には段階と進み具合を出します。
  最後の行の「フォルダ全体の確認」は動かせません。

## 速さ

- 2 回目からは、前回読み込んだ結果（`imgdupe.db`）を使い、**増えた・変わった画像だけ** を読み込みます。
  消えた画像は DB からも消します。
- 画像の読み込みは CPU の数だけ並行して行い、JPEG は縮小しながら読むので速く済みます。
- 見た目の比較は総当たりではなく、ハッシュを塊に分けて「同じ塊を持つものどうし」だけを比べます（Multi-Index Hashing）。
  合成データでの計測では、100 万枚・見た目一致の厳しさ 10 で約 5 秒（4 スレッド）でした（見た目一致の厳しさを上げるほど時間がかかります）。

- その日初めて終了する時に、裏で新しい版があるか確かめ、あれば「終了する前に更新しますか？」と聞きます
  （更新すると、次に起動した時から新しい版になります）。
- ツールバーの「アップデートを確認」（または「ヘルプ → アップデートを確認」）でいつでも確かめられます。
- 更新すると、GitHub のリリースから `imgdupe.exe` をダウンロードし、SHA-256 を確かめてから今の exe と入れ替えます（ツールバーから更新した時は起動し直します）。
  設定と DB はそのまま使えます。
- 自動の確認を止めるには、`imgdupe.ini` の `[imgdupe]` に `autoUpdateCheck=0` と書きます。

## 設定

「ツール → 設定…」（Ctrl+,）で、次の設定を画面から変えられます（全般・常駐解析・AI 解析・出典の照会・データ・そのほか の 6 ページ。v3.10）（中身は `imgdupe.ini` に保存します。ini を直接書き換えても同じです）。

| 終了する時に新しい版を確かめる | `autoUpdateCheck` | 1（する） |
| Windows と一緒に常駐解析を起動する | （HKCU の Run キー） | しない |
| WD14 タガーで画像にタグを付ける | `taggerEnabled` | 1（付ける） |
| CLIP で画像の内容を調べる | `clipEnabled` | 1（調べる） |
| 差分とみなす似ている度合い | `variantSimilarity` | 0.92 |
| 差分（AI）も出す（重複チェック画面） | `showVariants` | 1（出す） |
| GPU（DirectML）を使う | `taggerCpu`（1 なら CPU だけ） | 0（GPU を使う） |
| ファイル名の ID で投稿のタグと作者を調べる | `lookupEnabled` | 0（調べない） |
| 出典の投稿が消えていないか確かめる | `linkCheckEnabled` | 0（確かめない） |

## 監視フォルダの管理（v3.7）

ファイル → 監視フォルダの管理 で、監視フォルダの一覧（つながっているか・画像の数）を見て、次のことができます。

- **追加…**: 監視フォルダを足します（いくつも選べます）。
  - 足したフォルダの **中にある監視フォルダは、足したフォルダにまとめます**（一覧から外します。中の画像の解析の結果はそのまま使います）。
  - 足したフォルダが、もうある監視フォルダの中なら、足しません（もう監視しているので）。
  - この決まりは、監視フォルダの管理の「追加…」・解析の予約に追加・前回の設定を読む時も同じです。
- **監視をやめる**: 選んだ監視フォルダ（いくつでも）の監視をやめます。中の画像は休止中になり、解析の結果は残ります。
- **移動先を指定…**: ドライブレター・フォルダの名前が変わった・動かした監視フォルダの、新しい場所を指定します（解析はやり直しません。ダブルクリックでも）。
- **更新**: つながっているか・画像の数を確かめ直します（画面はすぐ開き、状態は確かめ終わったものから出ます。v3.8）。

## データの保護（v3.0）

一度作ったタグや解析は消さないようにしています（仕様は `データ保護の実装仕様.md`）。

- **見つからなくなった画像**（消した・監視フォルダの外へ動かした・ゴミ箱を空にした）は、DB から消さずに **退避** へ移します
  （`<データ>\archive\archive.db`）。退避するのは、作り直しに時間がかかるもの・作り直せないもの（タガーのタグ・手動で確定したタグ・
  CLIP のベクトルと、画像を見分ける情報）です。サムネイル・メタデータなどはすぐ作り直せるので退避しません。
- **休止中の画像**（ドライブを外した・監視フォルダが見つからない・監視をやめた）は、記録を残したまま、
  検索・重複・統計の結果に出しません。つなぎ直す・一覧に足し直すと、解析をやり直さずにすぐ戻ります（何ヶ月外していてもよい）。
- **動かした・名前を変えた画像**は、解析の結果（タグ・CLIP など）をそのまま引き継ぎます（v3.1）。大きさと更新日時が同じで、
  ファイル ID（同じドライブの中）・中身の SHA-256・ファイル名のどれかが合えば同じ画像とみなし、パスだけ書き換えます（解析はやり直しません）。
  退避にある画像が戻ってきた時（ゴミ箱から元に戻したなど）も、復元します。
- **ドライブレターが変わった**監視フォルダは、ドライブのシリアル番号とフォルダのファイル ID が同じなら、自動で新しい場所に付け替えます（v3.1。動作履歴とステータスバーに出ます）。
  ファイル → 監視フォルダの管理 →「移動先を指定…」で、自分でも指定できます（フォルダの名前を変えた・動かした時など）。
- つながっていないドライブの監視フォルダは、起動した時も一覧に残します（前は、見つからないフォルダを一覧から落としていました）。
- **ゴミ箱**（`$Recycle.Bin`）と `System Volume Information` はスキャンしません。
- **ドライブ記録**（v3.2）: 監視フォルダのあるドライブ（C: ・ネットワーク・CD と、直下に書けないドライブは除く）の直下に隠しフォルダ `.imgdupe` を作り、
  そのドライブの画像の守るもの（タガーのタグ・手動の確定・CLIP のベクトル・画像を見分ける情報。パスはドライブの中の相対パス）を `drive.db` に置きます。
  普段は PC 記録（このソフトの DB）を使い、10 分ごとに変わった分だけドライブへ記録します（常駐解析が。動いていなければ画面の側が）。
  - ドライブを外して 1 日たつと、PC 記録にあるそのドライブの分を片付ける（消す）か聞きます（ドライブへの記録の様子を見せます。ドライブへ記録していない分は退避します）。
    つなぎ直すと、ドライブ記録から取り込みます（サムネイル・メタデータなどは作り直し）。
  - ドライブ記録と PC 記録が食い違った時（別の PC で使った・ドライブへ記録する前に抜いた など）は、タガーの版・枚数・進み具合・作り終えた枚数・最後に書いた日時を
    並べて、どちらを使うか聞きます。選ばなかった方は退避に残します。
  - ドライブへの記録が 12 時間以上失敗し続けたら（ドライブがいっぱい・読み取り専用など）知らせます。
- **タガー・CLIP の版が上がった時**（v3.3）: 一から作り直しにしません。タガーは、前の版のタグを使い続けながら 1 枚ずつ新しい版のタグに置き換えます。
  CLIP は、前の版のベクトルで「類似画像」を探し続けながら、新しい版のベクトルを別のファイル（`vectors_clip.next.bin`）に作り、全部できたら切り替えます
  （前の版のベクトルは退避のフォルダ `archive` へ）。作り直しの途中の「内容検索」（言葉）と外の画像は、作り直し終えた画像から探します（結果の横にそう出ます）。
- **退避した解析結果**（ツール → 設定… → データ →「退避した解析結果…」）: 退避した画像の一覧（古い順。「置き場」の列に、この PC かどのドライブか）。選んだもの・「○ヶ月より前」のものを消せます（自動では消しません）。
- 退避の置き場（v3.4）: ドライブ記録があるドライブの画像は、そのドライブの `.imgdupe\archive.db` に退避します（ドライブと一緒に残り、別の PC でも戻せます）。
  C: などドライブ記録の無いドライブの画像は、この PC の `<データ>\archive\archive.db` に退避します。

## DB の形と大きさ

タグは、名前・種類・タグの由来を番号にして持ちます（v2.18 から。前は 1 行ごとに文字のまま、索引も 3 つ持っていました）。
タグの部分が前の約 1/4〜1/5 になり、検索・統計で読む量が減ります。メモリの使い方は前と同じです（大きなキャッシュは持ちません）。

- **初めての起動で変換**: 前の版の DB は、v2.18 を初めて起動した時に、新しい形へ少しずつ変換します（タグ付けのやり直しは要りません）。
  常駐解析が動いていれば解析が（タスクトレイの窓に「DB の変換」と進み具合）、動いていなければ画面の側が行います
  （下のステータスバーに %）。使いながら待てます。止めても続きから。100 万枚で数分〜十数分の見込みです。
  変換の並べ替えはメモリではなく一時ファイルで行います。
- **詰めて小さくする**: 変換した直後は、前の形の分が DB の中に空きとして残るので、ファイルはかえって少し大きくなります。
  変換が済むと一度だけ「詰めますか？」と聞きます（「ツール → 設定… → データ」の「DB を詰めて小さくする…」でいつでも）。大きさ・詰めた後の見込み・要る空き容量（詰めた後の大きさの約 2 倍）を出し、
  常駐解析が詰めます（その間は解析が止まります）。試算では、タグの多い DB で約 1/5 になりました。
- **索引の作り直し（v2.21）**: v2.18 で変換した DB は、タグの索引を、検索に要る列が全部入ったものに一度だけ作り直します（数分。解析か画面の側が自動で）。
  タグの検索が v2.18 より数倍速くなります。
- **検索の読み方の手入れ**: 常駐解析が、週に 1 回、検索のための数を取り直します（ANALYZE。少しだけ読んで見積もるので速い）。

## 設定と DB の場所

exe と同じフォルダ（インストールした場所）に `imgdupe.ini`（設定）と `imgdupe.db`（画像の情報。SQLite）を作ります。
AI の部品は同じ場所の `models` フォルダに入ります（入れた版は `models\installed.json`）。
前の版の `imgdupe_cache.bin` があれば、最初の 1 回だけ `imgdupe.db` に取り込みます（読み直しは要りません。取り込んだ後は消して構いません）。
exe のフォルダに書き込めない時（Program Files に置いた時など）は `%LOCALAPPDATA%\imgdupe` に作ります。
「ヘルプ → 設定のフォルダを開く」で開けます。`imgdupe.db` は消しても構いません（次回すべて読み直します）。
サムネイルは同じ場所の `thumbs_000.pack` などにまとめて保存します（小さなファイルを大量に作らないため）。

### 動作履歴（ログ）

おかしな動きをした時に後から確かめられるように、同じ場所の `logs` フォルダに動作履歴を残します。
画面は `imgdupe.log`、常駐解析は `indexer.log`。1 つが 4 MB を超えたら `imgdupe.1.log` … に回し、4 つまで残します。
「ヘルプ → 動作履歴（ログ）のフォルダを開く」か、タスクトレイのアイコンの右クリック「動作履歴（ログ）のフォルダを開く」で開けます。
残すこと: 起動・終了（前回きちんと終わらなかった時はそのこと）、落ちた時の例外と場所、設定、画面からの指示、待っている理由、
解析の段階ごとの枚数・失敗・かかった時間・速さ、止まった・譲った理由、10 分ごとの進み具合、重複探し・検索・アップデートの結果、
注意やエラーのダイアログの内容、GPU でまとめて流せなかった時など。おかしいと思ったら、この `.log` を送ってください。

## コマンドラインで使う

```
imgdupe.exe --cli D:\Photos E:\Backup               # 重複グループを imgdupe_result.csv / .html に書き出す
imgdupe.exe --cli D:\Photos -t 6 -o result         # 見た目一致の厳しさ 6、result.csv / result.html に書き出す
imgdupe.exe --cli D:\Photos --exact-only           # 完全一致だけ
imgdupe.exe --cli D:\Photos -q sample.jpg          # 1 枚と類似画像を探す
```

```
imgdupe.exe --index D:\Photos                     # 走査して DB に登録し、ハッシュ・サムネイル・メタデータ・タグを先に作っておく
```

オプション: `--include-flat`（単色に近い画像も比べる）、`--db <ファイル>`（DB の場所）、`-j <数>`（スレッド数）。

## 対応形式

JPEG・PNG・BMP・GIF・TIFF・WebP・HEIC/HEIF・AVIF・JPEG XR（Windows の画像コーデック WIC で読みます）。
WebP・HEIC・AVIF は、Windows に拡張機能（Microsoft Store の「WebP 画像拡張機能」「HEIF 画像拡張機能」など）が入っている時に読めます。
読めなかった画像の数は、検索の後に表示します。

## 判定のしくみ

- **完全一致**: ファイルの大きさが同じものだけ SHA-256 を計算して比べます。
- **見た目一致**: 画像を 32×32 に縮めて（EXIF の向きを反映）、横方向と縦方向の dHash（各 64 ビット）を作り、
  2 つのハミング距離の和が見た目一致の厳しさ以下で、平均の色も近いものを同じ見た目とみなします。
  似たもの同士を順につないでグループにします（A と B、B と C が似ていれば A・B・C は 1 グループ）。
- 切り抜き・回転（EXIF 以外）・大きな色調補正をした画像は、同じとは判定できません。

## ビルド

```
imgdupe/build.sh        # Windows 用の imgdupe/out/imgdupe.exe を作る（MinGW-w64。Linux からのクロスビルド / MSYS2）
imgdupe/build.sh test   # OS に依存しない部分のテスト
```

`imgdupe/build.sh` は `imgdupe.exe` と、それを中に入れたインストーラー `imgdupe_setup.exe` を作ります。

`main` ブランチに push すると GitHub Actions がテスト・ビルドし、リリース（`v<VERSION>.<連番>`）を作ります。
AI の部品は `imgdupe/models.src.json` に書きます。リリースの時に `imgdupe/tools/make_models_json.py` が
NuGet から ONNX Runtime を取り出し、Hugging Face のモデルをコミットに固定して、SHA-256 と大きさを入れた `models.json` を添付します。
使うモデルを変える時は `models.src.json` を書き換えて `main` に入れます（アプリの「アップデートを確認」で入れ替わります）。
メジャー.マイナーは `imgdupe/VERSION` で決めます。

DB には SQLite（`imgdupe/third_party/sqlite`、パブリックドメイン）、近似最近傍探索に hnswlib（`imgdupe/third_party/hnswlib`、Apache 2.0）、
AI の推論に ONNX Runtime（ヘッダーは `imgdupe/third_party/onnxruntime`、MIT。dll は AI の部品としてダウンロード）を使っています。

`python/imgdupe.py` は最初に作った Python 版です（`pip install pillow numpy` で動きます）。
